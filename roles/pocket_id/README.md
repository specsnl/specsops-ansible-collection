# specsnl.specsops.pocket_id

[Pocket ID](https://github.com/pocket-id/pocket-id), a passkey-only OIDC provider, as a
Podman Quadlet behind the host's Caddy. The role runs the pinned
`ghcr.io/pocket-id/pocket-id` image published on `127.0.0.1`, keeps its SQLite database on
the data disk and its encryption key in a `0600` file, and adds a Caddy site that proxies
the app URL's host to it.

Pocket ID is light: measured with v2.19.1 it uses 17 MiB idle and under 50 MiB at about
1,100 requests/s, so a 1 GB VM is plenty.

## Variables

| Variable                           | Default                       | Description                                     |
|------------------------------------|-------------------------------|-------------------------------------------------|
| `pocket_id_version`                | —                             | Image tag, e.g. `v2.19.1`                       |
| `pocket_id_image`                  | `ghcr.io/pocket-id/pocket-id` | Image, without the tag                          |
| `pocket_id_app_url`                | —                             | Public URL, e.g. `https://id.example.com`       |
| `pocket_id_encryption_key`         | —                             | Key for the secrets in the database, ≥ 16 bytes |
| `pocket_id_data_dir`               | `/srv/pocket-id`              | Data directory on the data disk                 |
| `pocket_id_data_dir_require_mount` | `true`                        | Fail when the data would land on `/`            |
| `pocket_id_port`                   | `1411`                        | Host port, published on `127.0.0.1` only        |
| `pocket_id_user`                   | `pocket-id`                   | System user the container runs as               |
| `pocket_id_caddy_sites_dir`        | `/etc/caddy/sites`            | Where the Caddy site file goes                  |

`pocket_id_version`, `pocket_id_app_url` and `pocket_id_encryption_key` are required.

## Requirements

The role installs neither Podman nor Caddy. Run `specsnl.specsops.podman` and
`specsnl.specsops.caddy` first.

The `caddy` role ships no Caddyfile, and this role only writes a site file to
`/etc/caddy/sites/pocket-id.caddy`. The Caddyfile you deploy has to import that directory:

```caddyfile
import /etc/caddy/sites/*
```

Without it Caddy is reloaded but does not serve the site.

## The encryption key

Pocket ID encrypts the secrets in its database with this key. Generate it once and keep it
in your secret store:

```bash
openssl rand -base64 32
```

The key has to stay the same for the life of the data: a restored database is unreadable
without the key it was written with. Keep it with, but not in, the backups of the data
directory.

The role writes it to `/etc/pocket-id/encryption-key`, `0600`, without a trailing newline,
and mounts it into the container read-only for `ENCRYPTION_KEY_FILE`. The file belongs to
`pocket_id_user`, not root: the image's entrypoint drops from root to `PUID`:`PGID` before
Pocket ID reads it. The task that writes it runs with `no_log`.

## The data directory

`pocket_id_data_dir` is mounted as `/app/data` and holds the SQLite database
(`pocket-id.db`) and uploaded images. It belongs to `pocket_id_user`, mode `0700`, and the
role passes that user's uid and gid to the container as `PUID` and `PGID`.

As with `postgresql`, the role fails when the directory, or the nearest existing directory
above it, is on the root filesystem. A data disk that failed to mount would otherwise get a
fresh, empty database on the OS disk. The role does not mount anything: mount the volume
first, e.g. with `block_volume`. Point `pocket_id_data_dir` below the mount point, as the
image's entrypoint takes ownership of everything in the directory, `lost+found` included.
Set `pocket_id_data_dir_require_mount: false` to keep the data on `/` on purpose. The
Quadlet also carries `RequiresMountsFor`, so the container does not start at boot before
the volume is mounted.

## The container

`/etc/containers/systemd/pocket-id.container` runs the image with:

- `PublishPort=127.0.0.1:<pocket_id_port>:1411`, so only Caddy reaches it;
- `APP_URL`, `TRUST_PROXY=true` for the client address Caddy forwards, and
  `ANALYTICS_DISABLED=true`;
- SQLite, Pocket ID's default.

Quadlet units are generated by systemd, so they cannot be enabled: the Quadlet's
`[Install]` section starts `pocket-id.service` at boot. A change to the Quadlet or the key
restarts it. The first start pulls the image, so `TimeoutStartSec` is raised to 15 minutes.
Logs are in `journalctl -u pocket-id`.

## The Caddy site

`/etc/caddy/sites/pocket-id.caddy` serves the app URL's host and proxies everything to
`127.0.0.1:<pocket_id_port>`:

```caddyfile
id.example.com {
    reverse_proxy 127.0.0.1:1411
}
```

Caddy gets the certificate itself. A change reloads Caddy.

## Logging in

Pocket ID has no passwords: users sign in with a passkey only. Create the first admin at
`https://<host>/setup` and register a passkey for it.

An admin can create a one-time login code for any user in the admin UI. The user signs in
with it once, on a new device or after losing their passkey, and registers a new passkey.

### Account recovery from the console

When no admin can sign in, create a one-time access token on the host, e.g. over the UpCloud
console:

```bash
sudo podman exec --user "$(id -u pocket-id):$(id -g pocket-id)" pocket-id \
  /app/pocket-id one-time-access-token <username or email>
```

It prints a link that signs the user in once, after which they register a new passkey.
Running it as `pocket_id_user` keeps any file it creates in the data directory readable by
Pocket ID.

## Containers

In a container the role writes the user, directories, key, Quadlet and site, but does not
start Pocket ID or reload Caddy.

## Example

```yaml
- hosts: identity
  become: true
  roles:
    - specsnl.specsops.firewall
    - role: specsnl.specsops.block_volume
      vars:
        block_volume_devices:
          - storage_uuid: "{{ data_volume_uuid }}"
            label: data
            mount_point: /srv/data
    - specsnl.specsops.podman
    - specsnl.specsops.caddy
    - role: specsnl.specsops.pocket_id
      vars:
        pocket_id_version: v2.19.1
        pocket_id_app_url: https://id.example.com
        pocket_id_data_dir: /srv/data/pocket-id
        pocket_id_encryption_key: "{{ vault_pocket_id_encryption_key }}"
```
